# Baseline comparison

A detector is only interesting relative to
what a simpler or differently-scoped method would catch. This page documents the
baselines this project ships (two rule baselines and two recorded real LLMs) and the head-to-head result
on the curated gold set (see [`ground_truth.md`](ground_truth.md) for the gold
set itself).

Run it yourself:

```bash
python3 -m telemetry_contracts.cli compare-baselines \
  --gold benchmarks/ground_truth/curated.jsonl
```

All methods are scored through the **identical** pipeline
(`telemetry_contracts.evaluation.score_gold_set`) over the same 112 hand-labeled
`(sample, bug-class)` items, so the comparison is apples-to-apples. Every method
sees only `(events, bug_class)` — never the gold label or rationale.

## The baselines

These are **capability baselines**, chosen to answer a specific question, not
claimed state-of-the-art detectors. Their definitions are frozen before the
comparison is snapshotted and no threshold is tuned on the gold set.

- **rule-light** — a deliberately naive detector that checks only whether an
  *obvious field name* is present (e.g. `trace_id`, `duration_ms`). No
  thresholds, no statistics, no failure gating, no value inspection. It answers:
  *what would a keyword linter catch?* It is value-blind, so it misses raw
  secrets hidden in innocently-named fields, and it has no statistical notion, so
  it cannot see unbounded cardinality at all (that class is out of scope for it).

- **semantic-convention-only** — flags solely missing OpenTelemetry
  semantic-convention fields (trace context, span duration, exception/status
  fields). It answers: *is convention conformance the same as correctness?* For
  sensitive values, unclassified identifiers, and unbounded cardinality the
  conventions define no detector, so those classes are reported **out of scope**
  — a coverage result, not an accuracy penalty. We therefore report both an
  all-class score (which shows the coverage limit) and a covered-class score
  (which is the fair within-scope accuracy).

- **Real LLM, zero-shot** (`anthropic/claude-haiku-4.5`, `openai/gpt-4.1-mini`).
  Each gold item is sent once, through OpenRouter, with the prompt built by
  `build_llm_prompt` (bug-class name, its definition, and the events as JSON;
  no label, no rationale, no examples). Decoding: temperature 0, max 200
  tokens. The raw responses, served model id, token usage and cost of every
  call are committed under `results/llm_baseline/*.raw.jsonl`; the parsed
  verdicts are in `benchmarks/baselines/llm_*.json`, which the harness replays
  offline so the comparison stays reproducible without network access.
  Re-querying the API can give different answers; the committed file is the
  record. Every response was parseable (0 scored as NO by fallback). Total
  cost of both runs: $0.077 (`results/api_costs.jsonl`).

- **recorded-surrogate** (opt-in, `--cache benchmarks/baselines/llm_recorded.json`).
  The earlier hand-written over-flagging policy that exercised the replay
  harness before real responses were recorded. It is not an LLM and is no
  longer part of the headline comparison.

## Reading the LLM rows

Both LLMs are at least as accurate as the tool on this set. Claude Haiku 4.5
gets every item the tool gets right plus four of the tool's documented hard
cases (`mc-hard-altkey`, `sv-hard-b64`, `uc-hard-smallsample`,
`us-hard-altname`); the paired difference (0 vs 4 discordant) is not
significant at n = 112 (exact p = 0.125). GPT-4.1-mini ties the tool (3 vs 3).
The hard cases were written by the gold-set author to document the tool's
field-keyed incompleteness, and a model that reads the bug-class definition
semantically handles them. We therefore do not claim an accuracy advantage
over LLMs. What the tool offers relative to them is cost and operational
profile: it is deterministic, offline, needs no API key, and scans the 116,420
events of the RQ3 corpus in minutes on a laptop, where a per-event LLM audit
would need one model call per (sample, class) pair.

## Threats to validity

- **Curated, balanced, single-author set.** The numbers describe the curated
  conformance set, labelled by one author; see `docs/evaluation/annotation/`
  for the second-annotator protocol that is still outstanding.
- **Author-designed rule baselines.** rule-light and semantic-convention-only
  are intentionally simple; covered-class metrics and the win/loss lists are
  reported to limit strawman risk.
- **LLM prompt.** One zero-shot prompt, no tuning. The prompt includes each
  class definition, which names the recognized fields; this helps the LLMs and
  is the same information the tool encodes.
- **One sample per model.** temperature 0 does not guarantee identical
  outputs on re-query; the committed raw log is authoritative.

## Reproducing

```bash
# Offline replay of the committed responses (no network):
python3 -m telemetry_contracts.cli compare-baselines \
  --gold benchmarks/ground_truth/curated.jsonl --format json

# Re-record the LLM responses (network, OPENROUTER_API_KEY, about $0.08):
python3 scripts/run_llm_baseline.py --model anthropic/claude-haiku-4.5
python3 scripts/run_llm_baseline.py --model openai/gpt-4.1-mini
```

`tests/test_baselines.py` locks the replayed numbers.
